Card-issuance 隐私与配置安全复查记录

日期：2026-11-18（北京时间）。对 `338216b` 做了一轮代码审查，重点是买家隐私数据泄露和误配置导致的资金风险。

**结论**

- 未发现 SQL 注入、XSS、CSRF 或越权取卡问题；PR #2 / #3 的取卡授权、入账去重、事务一致性逻辑复查无误。
- 发现并修复 6 个问题：查单耗时泄露邮箱是否下过单；HTTP 直连公网部署跳过全部启动安全检查；生产环境可开启模拟支付；后台会话没有有效期；`python -m app.main` 以调试模式监听公网；`data/`、`backups/` 目录对同机其他用户可读。

**修复**

| 问题 | 修复后行为 |
| --- | --- |
| 查单时邮箱没有订单就不做密码哈希，响应快约一个 PBKDF2 的时间，可借此批量探测某个邮箱是否在本店买过东西；后台登录同理可探测管理员用户名 | 查单固定做 5 次（填订单号时 1 次）哈希，后台登录用户名不存在时也做一次哈希，耗时与数据无关 |
| 启动检查只在 `APP_BASE_URL` 为 https 时生效。按 `.env.example` 手动部署成 `http://公网IP:端口` 时，`APP_SECRET=secret`（可伪造后台会话）、`ADMIN_PASSWORD=change-this-admin-password` 都能启动，后台的全部卡密和买家邮箱随之暴露 | HTTPS 或 `APP_BASE_URL` 不是 localhost / 127.0.0.1 / ::1 时一律按生产环境检查 |
| `ENABLE_MOCK_PAYMENTS=1` 误开在线上，任何人点“模拟支付成功”即可免费拿卡 | 生产环境开启模拟支付拒绝启动 |
| 后台会话 Cookie 只在退出或改密码时失效，被盗后长期可用 | 登录满 `ADMIN_SESSION_HOURS`（默认 12）小时须重新登录；升级前签发的旧会话须重新登录一次 |
| `python -m app.main` 以 `debug=True` 监听 `0.0.0.0`，Werkzeug 调试器可执行任意代码 | 只监听 127.0.0.1，调试模式需 `FLASK_DEBUG=1` |
| 容器以 root 写入 `data/`，数据库文件默认 0644，同机其他用户可读卡密和买家信息 | `setup.sh` / `update.sh` 把 `data/`、`backups/` 设为 700 |

README 补充：宿主机 Nginx / 宝塔反代时端口只绑定 127.0.0.1 并设置 `TRUSTED_PROXY_COUNT=1`，否则可直连伪造 `X-Forwarded-For` 绕过失败次数限制。

**已知的剩余风险（未改动）**

- 唯一金额 7 天冷却 + 每个价位 100 个尾数：攻击者用多个 IP 和随意填写的邮箱反复下单、不付款，可在数小时内占满某个价位的尾数，该价位 USDT 下单失败最长 7 天。缓解：后台调大 `max_slots`（最多 1000），或降低 `ORDER_CREATE_LIMIT_PER_HOUR`。
- 任何人对某个邮箱连续输错 8 次取卡密码，该邮箱 15 分钟内无法查单（下单浏览器不受影响）。
- 订单中的买家邮箱、下单 IP、卡密明文长期保存，没有自动清理。
- HTTP 直连模式下管理员密码、取卡密码、卡密明文传输，生产环境必须使用 HTTPS。
