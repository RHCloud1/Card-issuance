Card-issuance 安全与对账加固记录

日期：2026-11-10（北京时间）。共三轮外部审查（公网黑盒 + 本地复现）加一轮本地渗透测试，分两个 PR 修复。

**结论**

- 前台取卡授权、库存预占、管理员会话、响应头：已修复，PR #2 已部署到线上（`96c1457`）。
- 资金对账（付款归属、入账唯一性、人工补单去重、账本事务一致性）：PR #3 已修复。
- 按“小规模、小范围使用”的定位做了折中：**不做每单独立收款地址**（HD 钱包归集需要每个地址 13–27 TRX 手续费，运维成本高），改用“长时间不复用金额 + 有歧义就转人工”。
- 测试：64 项单元测试 + 部署脚本测试通过，GitHub Actions Python 3.12/3.13 通过。新增的 25 项回归用例都是攻击场景的复现，PR #3 的 10 项新用例中 9 项在修复前的代码上失败。

**PR #2：前台授权、库存与会话（已部署）**

| 问题 | 修复后行为 |
| --- | --- |
| 只凭邮箱即可取走未设密码订单的卡密 | 下单必须设置 6–20 位取卡密码；邮箱本身不再授予查看权限，旧的无密码订单只有下单浏览器可见 |
| 查单暴露订单号，取卡密码可无限尝试 | 查单需邮箱 + 密码，只展示密码匹配的订单；查单和订单页解锁共用失败计数，同一 IP 或邮箱 15 分钟 8 次后锁定 |
| 一次匿名查询触发最多 50 次密码哈希 | 空密码不计算哈希，每次最多校验 5 笔订单 |
| 不付款即可占光库存 | 同一邮箱最多 2 笔、同一 IP 最多 3 笔待支付订单，同一 IP 每小时最多 10 单（写锁内检查） |
| 管理员退出或改密后旧 Cookie 仍可重放 | `admin_users.session_version`：退出和更换 `ADMIN_PASSWORD` 时递增，旧会话全部失效 |
| Cookie 缺 Secure、缺 HSTS 和防嵌入 | HTTPS 下 Secure Cookie、HSTS、`X-Frame-Options: DENY`、`frame-ancestors 'none'`、`nosniff` |
| 可用示例 `APP_SECRET` 启动并伪造会话 | 示例值拒绝启动；HTTPS 下密钥须至少 32 位 |
| USDT 迟到付款发给复用同一金额的新订单 | 冷却期长于迟到窗口；同一入账可能对应多笔订单时不自动发卡 |
| 人工补单 `MANUAL:` 前缀绕过链上去重 | 补单填已登记交易号时直接认领该入账 |
| 更换收款地址后漏扫旧订单 | 按订单保存的地址分别扫描 |
| 订单页状态查询同步扫链、占住 worker | 状态接口只读数据库，扫描在后台线程执行 |
| 旧 Caddy 部署缺 `TRUSTED_PROXY_COUNT` | `update.sh` 自动补 `TRUSTED_PROXY_COUNT=1` |
| 跨币种价格排序错乱 | 先按币种分组再按价格排序 |

**PR #3：资金对账与运维加固**

| 问题（本地均已复现） | 修复后行为 |
| --- | --- |
| 已完成订单的金额立即复用，旧买家重复付款被发给新买家 | 任何订单用过的金额 7 天内不再分配（含已完成）；重复付款留在“未匹配” |
| 一笔交易内多笔 Transfer 只记第一笔 | 每笔单独记账，第 2 笔起记为 `交易号#2`（TronGrid 入账列表不返回事件序号，按稳定顺序编号） |
| 补单填 tronscan 链接绕过去重 | 从文本中提取 64 位交易哈希后统一去重；含多笔入账的交易须在“链上入账”页逐笔指派 |
| 多付的入账可指派给已发货订单并标为 matched | 拒绝；已发货订单不接受新的付款流水，多付款留待退款 |
| 发卡与入账状态分两次提交 | 入账状态在 `fulfill_order` 同一事务内更新，中途失败整体回滚 |
| 切换代币合约或接口后旧订单判定改变 | 有未结清 USDT 订单时禁止修改 `token_contract` / `api_base` |
| 生产环境缺管理员配置时使用公开默认账号；旧管理员不清理 | HTTPS 下必须设置 `ADMIN_USERNAME` 与至少 12 位 `ADMIN_PASSWORD`，否则拒绝启动；`.env` 之外的管理员启动时删除；`setup.sh` 要求密码至少 12 位 |
| 大数量订单囤货 | 同一 IP 的待支付订单合计最多预占 10 张卡密 |
| 工单刷屏、超大请求体 | 工单每 IP 每小时 5 张；请求体上限 5MB |

**新增配置项**（均有默认值，无需修改 `.env`）

`ORDER_MAX_PENDING_PER_CONTACT=2`、`ORDER_MAX_PENDING_PER_IP=3`、`ORDER_CREATE_LIMIT_PER_HOUR=10`、`ORDER_MAX_PENDING_CARDS_PER_IP=10`、`QUERY_MAX_FAILURES=8`、`TICKET_LIMIT_PER_HOUR=5`

**已知的剩余风险（接受）**

- 固定地址收款下，超过 7 天的迟到或重复付款可能与复用同一金额的新订单混淆，需要管理员在“链上入账”页人工核对。
- 查单成功后没有总频率限制；管理员登录只按 IP 限制失败次数（后台路径隐藏、密码随机长串）。
- 支付宝/微信接口尚未实现，相关通道应保持关闭。

**线上运维操作**

- 2026-11-10 关闭了线上的支付宝通道（未接入接口，买家下单后无法付款且会占库存）。
