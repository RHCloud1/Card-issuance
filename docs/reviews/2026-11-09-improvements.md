**已完成的修复**

| 问题 | 当前行为 |
| --- | --- |
| 取卡密码可被订单页面绕过 | 下单浏览器获得该订单的签名会话授权；其他浏览器需要正确密码。查询页和订单页共用授权，订单响应禁止缓存 |
| 关闭模拟支付后仍可发卡、跨通道发卡 | `ENABLE_MOCK_PAYMENTS` 默认关闭；同时核对环境开关、数据库启用状态和订单通道；发货函数核对通道，拒绝流水跨订单复用 |
| 重复或并发回调重复出货风险 | 履约事务、流水校验和幂等结果经过重复及并发回调测试 |
| 预占卡密被作废后库存滞留 | 仅 available 卡密允许作废；已预占/已售出卡密后端原子拒绝，页面不再提供相应按钮 |
| 异常订单剩余卡密一直被预占 | 金额、过期或库存异常记录支付事件并释放剩余预占；维护逻辑也清理旧版遗留的异常预占 |
| 首次多个 worker 初始化冲突 | 结构和默认数据分别事务串行化；管理员幂等 upsert；WAL 初始化提前设等待时间并有限重试 |
| 后台登录可重定向到外部地址 | `next` 仅接受安全本地路径，拒绝外部地址及编码后的危险形式 |
| `.env` 中含 `$`、引号或反斜杠的密码改变 | 写入时按 Compose 的规则编码字面值，真实 Compose 配置解析回归验证原值保留 |
| 运行中打包 SQLite/WAL 不保证一致性 | 新增 SQLite online backup，验证快照后再归档，备份文件权限设为 600；备份失败则在拉取更新前停止 |
| 自定义数据库路径可能跳过备份 | 更新从运行容器的实际 `DATABASE_PATH` 生成快照，不再依赖宿主机文件扩展名判断 |
| Debian 使用了 Ubuntu 的 Docker 源 | 按系统 ID 选择对应官方源，不支持的系统或无效代号在修改主机前退出 |
| 容器启动后过早报告部署成功 | 部署/更新检查容器内 HTTP；内置 Caddy 模式另检查正常证书的 HTTPS；失败输出日志并非零退出 |
| 无支付方式或缺货时下单提示不清 | 购买页显示原因并禁用创建订单，取卡密码输入改为掩码显示 |
